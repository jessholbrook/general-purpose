  <action>
Create the full Ghost 6 theme scaffold from scratch. Every file is new — this is a greenfield project with only .git and .planning currently existing.

**package.json** — Theme name MUST be "general-purpose" (locked decision). Include these exact fields:
- `"name": "general-purpose"`
- `"description": "Jess Holbrook's personal site theme"`
- `"version": "1.0.0"`
- `"license": "MIT"`
- `"author": { "name": "Jess Holbrook" }`
- `"engines": { "ghost": ">=6.0.0" }`
- `"config": { "posts_per_page": 15, "image_sizes": {}, "card_assets": true }`
- `"type": "module"`
- Scripts: `"dev": "rollup -c --environment BUILD:development -w"`, `"build": "rollup -c --environment BUILD:production"`, `"zip": "npm run build && bestzip $npm_package_name.zip assets/ *.hbs partials/ package.json"`, `"test": "gscan ."`, `"pretest": "npm run build"`
- devDependencies: rollup, @rollup/plugin-node-resolve, rollup-plugin-postcss, rollup-plugin-livereload, @rollup/plugin-terser, postcss, postcss-preset-env, gscan

**rollup.config.js** — ESM format (matches `"type": "module"`). Input: `assets/js/main.js`. Output: `assets/built/main.js` (iife format). Plugins: @rollup/plugin-node-resolve, rollup-plugin-postcss (extract to `assets/built/screen.css`, minimize in production), livereload watching `assets/built` in dev mode, @rollup/plugin-terser in production. Use `process.env.BUILD === 'production'` to detect mode. The JS entry file must `import '../css/screen.css'` so PostCSS processes it.

NOTE: Use `@rollup/plugin-terser` (not `rollup-plugin-terser` which is deprecated). The import is `import terser from '@rollup/plugin-terser'` — no destructuring needed.

**default.hbs** — Base layout. MUST include ALL required Ghost helpers:
- `{{ghost_head}}` in `<head>` (REQUIRED, fatal gscan error if missing)
- `{{ghost_foot}}` before `</body>` (REQUIRED, fatal gscan error if missing)
- `{{body_class}}` on the `<body>` tag
- `{{{body}}}` (TRIPLE curly braces — double braces would HTML-escape content)
- `{{asset "built/screen.css"}}` for stylesheet
- `{{asset "built/main.js"}}` for script
- `{{meta_title}}` in `<title>`
- `lang="{{@site.locale}}"` on `<html>`

**index.hbs** — Post listing. Wrap in `{{#foreach posts}}` block with basic post output (title, excerpt, url). Include pagination via `{{pagination}}`.

**post.hbs** — Single post. MUST include `{{post_class}}` on the article wrapper (REQUIRED by gscan). Use `{{title}}`, `{{content}}`, `{{date}}`.

**page.hbs** — Static page. Similar to post.hbs but for pages. Include `{{title}}` and `{{content}}`.

**error.hbs** — Standalone error page. MUST NOT use `{{ghost_head}}`, `{{ghost_foot}}`, or extend default.hbs. It is a complete HTML document on its own. Use only `{{statusCode}}`, `{{message}}`, and `{{asset}}` helper. Include minimal inline or linked CSS via `{{asset "built/screen.css"}}`.

**assets/css/screen.css** — Minimal source CSS. Just a basic reset and body styling placeholder. This is the source file that PostCSS processes.

**assets/js/main.js** — Entry point. Must `import '../css/screen.css';` at the top (so Rollup/PostCSS picks it up). Can be otherwise minimal (a console.log or empty body).

**partials/.gitkeep** — Empty file to ensure the partials directory exists in git.

**.gitignore** — Include: `node_modules/`, `assets/built/`, `*.zip`, `.ghost/`. Do NOT ignore .hbs files or package.json.

Create the GitHub Actions workflow file and push everything to a new public GitHub repo.

**.github/workflows/deploy-theme.yml** — Exact content per locked decision:
```yaml
name: Deploy Theme
on:
  push:
    branches:
      - main
jobs:
  deploy:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - name: Deploy Ghost Theme
        uses: TryGhost/action-deploy-theme@v1
        with:
          api-url: ${{ secrets.GHOST_ADMIN_API_URL }}
          api-key: ${{ secrets.GHOST_ADMIN_API_KEY }}
```

Then create the public GitHub repo and push:
1. `gh repo create general-purpose --public --source=. --push` (uses GitHub CLI)

2. Verify the workflow file exists and is valid YAML.
